# Hard constraints

Эти ограничения **нельзя нарушать** — это продуктовые требования локального контура. Правки, меняющие эти значения, считаются регрессом.

## Параметры инференса (Modelfile / любые настройки Ollama)

- `num_ctx = 4096` — строго
- `num_predict = 256` — строго (это значит, любой один вызов LLM ≤256 output-токенов)
- `num_batch = 1`
- `num_parallel = 1`

## Параметры в `app/core/config.py`

- `planner_max_tokens`, `coder_max_tokens`, `fixer_max_tokens` — **все ≤256**. OpenAI-совместимый API параметр `max_tokens` перекрывает `num_predict` из Modelfile, поэтому оба должны быть согласованы.
- Если в коде или `.env` видишь значение `>256` для любого `*_max_tokens` — это баг, откатывать.

## Железо

- Пиковое потребление VRAM ≤ 8.0 GB (измеряется через `nvidia-smi`). Модель должна полностью лежать на GPU, без CPU offload.
- Квантизация разрешена.

## Архитектурные ограничения

- Модель — **только локальная open-source через Ollama**. OpenAI, Anthropic, любые внешние AI API — **запрещены** (это дисквалификация).
- RAG / шаблоны / базы знаний — **только локально**, в поставке.
- Зависимости и команды запуска должны быть воспроизводимы локально по README.

## Как проектировать под 256 output-токенов

- Не пытайся обойти лимит через несколько независимых вызовов LLM, которые потом склеиваются — это и породило текущий баг с дублями функций (см. историю `_merge_steps` → `_format_multistep_task`).
- Если промпт сложный и не влезает — лучше отдать обрезанный код fixer-циклу, чем генерить несколько самодостаточных скриптов и клеить.
- Planner (256 tokens) выдаёт план, Coder (256 tokens) получает весь план **одним промптом** и пишет один связный Lua-файл. Fixer чинит синтаксис итеративно.
- Тестируй изменения на эталонном запросе (простой, 1 шаг) — именно на нём идёт замер VRAM.
- Системные промпты в `prompts.py` расходуют **input**-токены (из 4096 `num_ctx`), а не **output** (256 `num_predict`). Удлинять их ради подавления HTML-мусора — нормально. User-промпты тоже можно удлинять, пока общий input << 4096. Единственный неприкасаемый потолок — output ≤ 256.
- Модель регулярно выплёвывает HTML-осколки (`"kw">`, `"cmt">`) и прозу-префикс (`PingWin_`, `lua`, `Копировать код`) перед самим кодом. Это чистит `pipeline._strip_fences`. При любой правке этой функции прогоняй её минимум на двух фикстурах: **(а)** чистый Lua без префикса, **(б)** реальный грязный вывод вида `PingWin_\nlua\nКопировать код\n"kw">function ...` — он должен выйти валидным Lua, начинающимся с `function`.

## Что можно менять свободно

- Содержимое промптов (`app/services/prompts.py`)
- Логика пайплайна (`app/services/pipeline.py`), пока она укладывается в ограничения выше
- Валидатор, RAG, постобработка вывода
- Ollama-модель (тэг) — при условии `VRAM ≤8 GB` и `num_predict=256`
